# Official undergraduate rubric and implementation evidence

Transcribed from the undergraduate pathway table in the supplied PROJECT DETAILS.docx. The separate evidence crosswalk is not a second grade.

## Functionality & applied knowledge (25)
Five distinct screen roles with navigation, forms, lists/grids, gestures, dialogs, validation, start/progress/finish/reset, filter/aggregate, and two-device/emulator testing. Implement the required local smart helper and comparison baseline; record at least five normal/no-data/invalid/boundary/counterexample cases with expected/actual results. Report a suitable metric/sample size and a justified revision or limitation. Explain state changes and visible error recovery.

## Code quality & core concepts (15)
Reusable StatelessWidget and StatefulWidget composition, meaningful names, organized files, DRY logic, and useful comments in non-obvious code. Keep helper decision logic separate from widgets and label rules/statistics versus example-based models accurately. Explain state ownership, lifecycle cleanup, and data boundaries in ARCHITECTURE.md. Demonstrate Flutter/Dart understanding rather than copied code without explanation.

## UI/UX, creativity & user engagement (15)
Consistent Material interface, portrait/landscape responsiveness, accessible labels, contrast, text scaling, and appropriate animation. Show the helper suggestion/reason, accessible dismiss/override controls, and actionable no-data/invalid feedback; never silently save a suggested value. Demonstrate one user-centered creative interaction or problem-solving improvement. Include before/after design evidence, a peer usability observation, and a verified revision.

## Local data persistence (15)
Validated SQLite create/read/update/delete for both related entities and SharedPreferences settings. Show the parent-delete policy, refreshed derived values after edits/deletes, offline restart persistence, parameterized queries, sensible schema/data ownership, and clear failure feedback. Explain why each storage choice fits the data. No cloud app storage.

## Version control, engagement & Kanban (10)
At least 20 meaningful commits per person over the project; feature branches and pull requests. Apply the required ClickUp workflow: daily board updates, ownership/WIP policies, four dated snapshots, each member's completed task-to-code/test trace, and one flow improvement. Complete the four delivery checks: Kanban_Contribution_Evidence.pdf in the repository and every final ZIP; README board URL/file path; readable offline evidence with privacy/permission verification; one recorded task → code → test/review trace inside the 20–25 minute presentation. Record blockers honestly if encountered. Manufactured or last-minute history is not steady progress.

## Documentation & reflection (10)
Approved proposal, README setup/version/dependency notes, user guide, schema, ARCHITECTURE.md, report, contribution evidence, known issues, and required slides/video links. Required AI_FEATURE.md explains benefit, inputs/units, method/rationale/alternative, baseline, cases/metrics/sample size, counterexample, revision/limitation, and user-control/offline evidence. Record AI development assistance separately in AI_Usage_Log.md when used. Explain what you learned.

## Project 1 Q&A · mandatory (10)
Answer the balanced selection including required I1/I2/D1/D2/R4 during the team presentation using app behavior and code. Every member explains their contribution, state/data concepts, helper reasoning/evaluation, and a challenge/solution. Unsupported claims or unexplained generated code do not demonstrate understanding.

## Base total (100)
Up to 15 additional bonus points; individual evidence determines each student's grade.
